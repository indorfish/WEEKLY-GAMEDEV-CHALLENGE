ATTEMPTING A TAXONOMY OF GAMES

CLASSIFICATION BY PHYSICS
-   No (explicit) physics
-   Discrete (Cellular Automata)
-   2D Rigid Body
-   2D Soft Body
-   3D Rigid Body
-   3D Soft Body
-   Ragdoll

CLASSIFICATION BY PLAYER COUNT
-   Single-player
-   Two-player
-   Multiplayer

CLASSIFICATION BY GAME STRATEGY
-   Open/Exploration (there's nothing to 'win', just explore and interact)
-   Puzzle (solve a problem under constraints). Is every puzzle game simply a search problem?
    The game model exists in state A and it is your job to find a "path" (sequence of transforms)
    that puts the game in state B.
-   Zero-Sum, Adversarial (Only one player can win, and they must cause the other player(s)
    to lose e.g. Tekken or other fighting games)
-   Zero-Sum, Competitive (Only one player can win, but players do not necessarily interact directly; they compete for a finite resource for example Formula One with a tie-breaker)
-   N-player, Zero-sum
-   Team games
-   Tournament games
-   Resource management?

CLASSIFICATION BY CHANCE
-   Deterministic games
    -   Same input always gives same output
-   Non-Deterministic games
    -   Games of skill (you can rig the dice)
    -   Games of pure luck (e.g. Roulette)

CLASSIFICATION BY COMPUTATIONAL COMPLEXITY?
-   Memory complexity
    -   Finite State Games: there is an upper bound for memory usage i.e. we know that this game
        will never use more than 30kB of memory during runtime, because the game has only finitely
        many states.
    -   State-unbounded Games: games which can exist in arbitrarily-many states

CLASSIFICATION BY AESTHETICS
Aesthetics is an important part of the gaming experience. Unless you're an LLM, you probably do not interact with games via an API.
There are visual aesthetics and genre/stylistic aesthetics.
This taxonomy is bound to be the loosest.
